# test: verify the wicked sqlc upstream migration

## 1. Background and Current State

This repository is the downstream example for Stumble/sqlc. Its committed code
was generated by v2.3.0, while the approved migration uses v2.3.4 behavior as its
baseline and sqlc v1.31.1 as its upstream source.

Primary design: Stumble/sqlc `docs/changelogs/2026-09-08-sync-upstream-and-separate-wicked-codegen.md`
on branch `refactor/upstream-sync`.

## 2. Problem Model and End-to-End Behavior

Preserve the existing SQL, public generated APIs, caching, timeout, invalidation,
transaction, replica and serde behavior. Tests must own their PostgreSQL and
Redis instances because the suite recreates its database and flushes Redis.

## 3. Research, Findings, and Architecture Decision

The approved design regenerates from the new fork and compares against a fresh
v2.3.4 generation. In particular JSON fields are already json.RawMessage in that
baseline; v2.3.0's base64 JSON goldens are not the current expected behavior.
Keep wpgx v0.3.1 and dcache v0.1.3; do not upgrade the runtime as part of this test.

## 4. Implementation Design

Add an isolated test environment with random host ports, explicit pool/replica
configuration, and cleanup by owned container ID. Extend runtime coverage in
pkg/usecases. Make the SQLC binary selectable in generation targets and
regenerate checked-in repos without hand edits.

## 5. Verification and E2E Design

E2E Required: yes. Run generation, sqlc diff, Go compilation, the entire runtime
suite, and race tests against real PostgreSQL/Redis. Check cached and uncached
reads, commit/rollback invalidation, nil-cache writes, copyfrom, replicas and
JSON/null round-trips. Inspect every changed golden.

## 6. Human Decisions and Interaction

Implementation and publication of the fork and its downstream verification PR
are authorized. All fixes stay in the user's repositories; upstream PRs follow
successful verification of the complete fork.

## 7. Outcome and Evidence

- Regenerated all repositories using the migrated wicked backend. With the new
  activities copyfrom query included in both inputs, all 17 Go output files match
  a fresh v2.3.4 generation except for their development version comments.
- Added a real copyfrom example and runtime contracts for cache hits, negative
  caching, nullable pointer keys, JSON values, nil-cache writes, multiple
  invalidation targets, transaction commit/rollback, and both cache/DB timeouts.
- Replaced ambient test database configuration with owned containers and random
  loopback ports. Existing services and data were not used.
- Updated only three JSON golden values: base64 `W10=` / `e30=` become JSON
  `[]` / `{}`, matching the v2.3.4 json.RawMessage behavior. Inspected every diff.
- `make sqlc SQLC=/home/forge/sqlc/bin/sqlc`: passed.
- `make sqlc-verify SQLC=/home/forge/sqlc/bin/sqlc`: passed.
- `make lint-fix`: passed, zero issues.
- `make test`: passed on Go 1.25.7 against owned PostgreSQL/Redis.
- `go test -race -count=1 -p 1 -timeout 10m ./pkg/usecases`: passed on Go 1.25.7.
- `GOTOOLCHAIN=go1.26.2 go test -race -count=1 -p 1 -v -timeout 10m ./pkg/usecases`:
  passed; 14 suite cases plus two search subcases, with real PostgreSQL/Redis.
- Existing runtime dependency versions remain unchanged. No production database
  migration or deployment is required.

## 8. Remaining Work

Replica tests exercise generated API and connection selection against one test
database, not physical replication lag. The paired sqlc PR supplies the updated
generator; merge it before adopting these regenerated fixtures.
